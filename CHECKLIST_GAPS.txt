--- Authentication & Authorization ---
[Partial]  Managed identity provider (Auth0, Clerk, WorkOS, Cognito, NextAuth)
           Have: custom FastAPI JWT + Google Identity Services (OIDC ID-token, verified server-side).
           Not: Auth0/Clerk/Cognito. You own session bugs; you avoid vendor lock-in.
[Partial]  Enforce MFA for all users (especially admins)
           Exceeds on password accounts: TOTP is mandatory. Google OAuth is exempt. No extra admin-only step.
[Have]     Password policy: minimum 12 characters + complexity
           UserRegister: min 12 + at least one letter and one digit. Login of existing hashes unchanged.
[Have]     Argon2 or bcrypt for password hashing
           bcrypt via passlib CryptContext(schemes=["bcrypt"], deprecated="auto").
[Have]     Account lockout after 5–10 failed login attempts
           Redis auth:fail / auth:lock after 5 failed password logins, 15 min. Fail-open if Redis is down.
           Also: IP rate limit on /auth/login (10/min) and /auth/register (5/min). Google path not lockout-counted.
[Partial]  SSO (SAML or OIDC) for enterprise customers
           Consumer Google OIDC only. No SAML / WorkOS / multi-tenant IdP.
[Partial]  Short-lived access tokens (15 min) with refresh token rotation
           Access TTL is 30 min (not 15). Refresh now blocklists the presented refresh jti before issuing a new pair.
[Missing]  Store tokens in HttpOnly, Secure, SameSite cookies (never localStorage)
           Web: localStorage. Mobile: flutter_secure_storage (better). S-026 / ADR-004 specified, not built.
[Missing]  Session idle timeout 15–60 minutes
           JWTs are absolute TTL, not idle.
[Partial]  Session absolute timeout 8–24 hours
           Access 30 min is fine. Refresh TTL is 7 days (longer than 8–24 h).
[Partial]  Invalidate sessions on logout, password change, account suspension
           Logout blocklists access jti (+ optional refresh) in Redis. Inactive users 401. No password-change endpoint.
[Missing]  Rotate session IDs after privilege escalation
           No role-change flow that mints a new jti.
[Have]     RBAC or ABAC
           require_roles() + ownership checks (get_owned_business).
[Have]     Principle of least privilege
           Cannot self-register as admin. Cross-merchant resources return 404, not 403.
[Have]     Server-side authorization on every API call
           FastAPI Depends on protected routers.
[Partial]  Audit logging: who accessed what, when, from where
           audit_logs for admin approve/suspend/moderate. No IP. No login/failed-login events.

3. WHERE WE ALREADY MEET OR BEAT THE LIST
================================================================================

- Mandatory TOTP for password login (most lists only ask for optional MFA).
- JWT type claim so refresh/MFA tokens cannot be used as access tokens.
- Redis jti blocklist on logout; inactive users rejected.
- Two-layer authz: role + ownership (404 not 403).
- Admin cannot self-register.
- Google ID tokens verified server-side (audience + issuer).
- bcrypt; SECRET_KEY has no insecure default.
- Auth rate limits and upload MIME/size caps ARE in code (README §9 is stale).
- REST /api/v1, Pydantic, parameterized SQL, CORS allowlist.
- Hybrid Next.js SSR/CSR matching the page type.
- Redis cache with TTL + write invalidation; Redis optional (fail-open except AI lock).
- OpenAPI/Swagger; Flutter client generated from it; secure storage on mobile.
- Feature-branch hook, CI tests, ADRs (including ADR-004 for cookie auth).

4. KEY FEATURES MISSING (product / security capabilities that do not exist)
================================================================================

P0 — blocking for real public users
  - HttpOnly cookie session for web (S-026) while keeping Bearer for mobile
  - HTTPS + HSTS + security headers + CSP
  - True refresh-token rotation (revoke old refresh jti on each refresh)
  - Dependabot (or equivalent) on GitHub
  - Structured request logs + Sentry (or similar) + uptime check on /health
  - Privacy Policy, Terms, GDPR export/delete if any real person in EU/US uses the app
  - Stop collecting national ID until a legal basis and retention story exist

P1 — should land before calling it “production”
  - Password min 12 + complexity
  - Per-account lockout (not only IP rate limit)
  - Shorten refresh absolute lifetime (hours, not 7 days) or add idle timeout
  - S3 (or R2) + CDN for uploads; stop using container disk
  - Global API rate limit (Redis-backed) so replicas share buckets
  - GitHub branch protection: required CI + review on main
  - Auto-deploy on green CI
  - next/image + lazy/srcSet for galleries
  - Cookie consent when cookies are introduced

P2 — quality, not survival
  - TanStack Query or SWR
  - Consistent API error envelope
  - Playwright E2E for login / MFA / merchant / admin happy paths
  - app/error.tsx + skeletons
  - Lighthouse / Web Vitals in CI
  - Prettier + commitlint if you want the workflow items strictly checked
  - SSG/ISR for city/category indexes
  - Notification SSE/WebSocket instead of polling
  - Job queue (ARQ/Celery) if AI volume grows

Do not build unless the product needs them
  - Stripe / PCI (no payments today)
  - Microservices, Kafka, read replicas, sharding
  - Canary / blue-green / feature-flag platform
  - Datadog APM / Jaeger (Sentry + /health uptime is enough at this size)
  - Auth0/Clerk (optional replacement for custom JWT, not required to “pass” authz)

6. WHAT IS REALLY REQUIRED TO REACH “CHECKLIST QUALITY”
================================================================================

Two bars. Pick one. Cost differs by ~10x.

BAR A — Public internet MVP (honest production for a small audience)
  1. Finish S-026 cookie auth + CSRF (already designed).
  2. Security headers + CSP + HSTS at the reverse proxy or FastAPI middleware.
  3. Refresh rotation + password policy + account lockout.
  4. S3/R2 for photos.
  5. Dependabot + Sentry + UptimeRobot (or Railway health) + structured logs.
  6. Legal pages + do-not-collect national ID (or lawyer-approved purpose).
  7. Branch protection + auto-deploy.
  Time: roughly 2–4 weeks of focused engineering, one person who already knows this repo.
  Cash: ~$0–50/mo SaaS (Sentry, uptime, object storage) + domain/TLS (Railway).
  People: you. Optional: 1–2 day pentest later.

BAR B — Enterprise / SOC 2 shaped (every checkbox including SSO, queues, APM, canary)
  1. Everything in Bar A.
  2. Managed IdP or WorkOS SAML for enterprise SSO.
  3. Worker queue, feature flags, CDN in front of API, read-replica plan.
  4. Formal GDPR program, DPA, retention jobs, cookie CMP.
  5. Pentest + (if selling to enterprises) SOC 2 Type I/II over months.
  Time: months, not weeks.
  Cash: tens of thousands (audit + lawyer + pentest + vendors).
  People: engineer + privacy counsel + pentester + (later) auditor. Not a generic web agency.

Recommendation: Bar A. Bar B is theatre until you have paying customers and a data-processing reason.
